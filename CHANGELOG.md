# Changelog

## Unreleased

**Repositioned 2.0 as a real relaunch, not just a rebuild.** README and the Chrome Web Store listing led with a plain feature-list description carried over from v1.3; neither explained why this beats checking Chrome DevTools directly or asking the model to self-report its own queries, and the privacy reassurance was buried near the bottom of both documents instead of answering the single biggest hesitation ("is this reading my data?") up front. Added a `.agents/product-marketing.md` positioning doc (audience, differentiation, objections, brand voice) so README, the store listing, and any future copy pull from one source instead of drifting independently -- which is exactly what the earlier stale-docs audit found happening across platform-count and test-count claims. Rewrote both documents' opening sections around the actual insight (every assistant searches silently and never shows the real query) and moved privacy to the top. Light microcopy pass: `EmptyState.tsx`'s empty-panel subtitle now reassures a first-time user ("Nothing leaves your browser") -- the rest of the in-product copy was already appropriately terse and didn't need touching.

**Redesigned the extension icon.** The icon (`public/icons/icon{16,48,128}.png`) was still the v1.3-era glowing cyan/blue magnifying-glass-over-circuit-board artwork -- the exact "AI HUD" look the UI rebuild explicitly designed away from (see this file's "Visual redesign" entry below). Replaced with a flat magnifying glass in the real `--csr-accent` (`#8b93f0`) on a dark rounded-square tile built from the UI's own surface tokens (`#0c0e13` → `#12151c`), no glow or gradient on the mark. Hand-authored as one master SVG (`public/icons/icon-master.svg`) and rasterized to all three sizes with `rsvg-convert` (already installed locally, no new dependency); verified legible at 16px before replacing the real files.

**Fixed Gemini's real capture endpoint never being intercepted at all.** User-reported (2026-10-08): a live Gemini search that visibly cited sources in Gemini's own UI produced no keyword/sources in the overlay. Root cause: `GeminiContext.shouldIntercept` checked for lowercase `/generate`/`/stream` substrings, but the real message-generation RPC the web client actually calls is `.../assistant.lamda.BardFrontendService/StreamGenerate` -- PascalCase, and dot-joined to the preceding path segment rather than slash-joined -- so it silently never matched either check. Every previous "successful" Gemini capture (including the one used to confirm the earlier re-entrant-extraction fix) only ever came from incidental `batchexecute` side-calls that happened to carry query-shaped strings, never the real response. Fixed by matching on `BardFrontendService` directly. Also closed a real test-coverage gap: `shouldIntercept` had zero test coverage before this, which is exactly how a substring casing bug like this ships unnoticed -- added a dedicated test suite, confirmed red-before-green against the exact live URL.

**Fixed conversation-switching leaving the overlay stuck on stale data.** User-reported (2026-10-08): switching between earlier conversations (1 -> 2 -> 3 -> back to 2 -> 1) stopped updating the panel. Root cause: `conversationKey` in `src/content.tsx` was a `const` computed once when the content script first loaded. ChatGPT/Claude/Gemini are all client-side-routed SPAs -- clicking a different conversation changes the URL via the History API without a full page reload, so the content script never re-runs and never notices the switch; every save/restore kept targeting whichever conversation happened to be active at initial page load. Confirmed as a pre-existing bug, not a rebuild regression (identical in `archive/legacy-v1.3/src/conversation.ts`). Fixed by polling `location`/pathname every second for a conversation-key change and, on change, flushing the outgoing conversation's captures immediately, clearing the in-memory list, and restoring the new conversation's own persisted history (same path `init()` already used, now extracted into a shared `restoreConversation()` helper).

**Live verification pass found and fixed 5 real bugs (2026-10-08).** Browser-automation testing against real ChatGPT/Claude/Gemini sessions surfaced issues that unit tests couldn't catch, since they only appear against the real page/worker environment:
- An `AbortSignal` in a re-entrant fetch's `RequestInit` isn't structured-cloneable, so forwarding it to the extraction worker via `postMessage` threw a `DataCloneError` (ChatGPT).
- Same class of bug for a `Headers` instance in `RequestInit` (Claude) -- both fixed by a shared `sanitizeInit()` that strips `signal` and flattens `Headers` to a plain array of tuples before posting.
- A relative URL (e.g. `/api/...`) failed to resolve inside the worker's `blob:` realm, since the worker has no page-relative base URL -- this broke claude.ai entirely ("Connection lost"). Fixed by resolving against `window.location.href` before posting.
- `:root` custom properties never apply inside a Shadow Root -- the whole panel rendered fully transparent on ChatGPT. Fixed by moving all design tokens from `:root` to `:host` in `src/ui/tokens.css`.
- The panel auto-expanded on new captures and could visually cover the host page's own Send button -- the exact class of bug that broke a prior version of this extension for one of its users badly enough to cause an uninstall. Fixed by removing all auto-expand call sites; the panel only expands on an explicit user click now.

**Fixed Gemini's complete extraction silence -- the real cause wasn't schema drift, it was architectural.** The interceptor's hook-cycle-escape branch (taken whenever another script on the page also wraps `window.fetch` -- gemini.google.com does this for essentially every request) returned the worker-forwarded fetch directly, completely skipping platform detection and `extract()`. Gemini's `batchexecute` calls never once reached the code that would have processed them. Fixed by sharing one `attachExtraction` helper across both the direct and hook-cycle-escape paths in `src/interceptor.ts`. The same fix was independently confirmed to also restore Claude's search capture, which showed the identical "fetch re-entry detected" pattern (Datadog wraps `fetch` on claude.ai too) but was never previously confirmed broken or fixed, since the live pass hadn't yet triggered an actual `web_search` tool call there.

**Replaced the native `confirm()` dialog with an in-panel confirm.** Found immediately while using the "Clear all captures" button below for its own verification (2026-10-08): a native `window.confirm()` blocks the entire tab's main thread at the browser-chrome level until a human clicks it -- no automated check, keyboard event, or even a forced navigation can dismiss it programmatically. That's uncomfortably close to the exact class of bug that caused a prior version's uninstall (the overlay freezing/covering the host page). `Header.tsx` now shows an inline "Clear all? Yes / No" row in place of the normal header buttons instead, with a 6-second auto-cancel so an accidentally-opened confirm doesn't linger.

**Added a "Clear all captures" button.** There was no way to clear persisted captures short of wiping the extension's `chrome.storage.local` directly -- surfaced as a real gap when a stale false-positive capture (see the Gemini fix below) kept reappearing after the underlying bug was already fixed, since the fix stops new bad captures but doesn't retroactively purge old ones. Added a 🗑 button to the panel header (`src/ui/components/Header.tsx`), wired to the existing `replaceAll([])` store primitive, with a confirm prompt since it's not undoable.

**Perplexity support removed.** Live testing (2026-10-08, twice, to rule out a fluke) found zero matching network traffic for a real search on perplexity.ai -- the page has migrated to a Relay/GraphQL-based delivery mechanism (likely WebSocket) that `PerplexityContext.shouldIntercept`'s REST/SSE endpoint assumptions can never match again. Rather than guess blind at a rewrite with no real traffic to verify against, Perplexity was removed from the active extension: `src/platforms/perplexity.ts`/`.test.ts` moved to `archive/perplexity-unsupported/` (kept for reference, not wired into the build), deregistered from `interceptor.ts`, dropped from `manifest.json`'s `content_scripts.matches`, and its UI color tokens removed. Docs updated to say three supported platforms (ChatGPT, Claude, Gemini), not four. See `ROADMAP.md` and `archive/perplexity-unsupported/README.md` for the full investigation.

**Fixed a real Gemini false-positive.** `src/platforms/gemini.ts`'s regex-fallback "quoted term" matcher treated `'` as a quote delimiter alongside `"`. Since this text is JSON-based (where `'` never opens/closes a string), an apostrophe inside an ordinary contraction like "I've" got misread as an opening quote -- everything up to the next apostrophe/quote was captured as a fake search query (observed live: `"ve been curious about"`, a fragment of the assistant's own answer). Fixed by restricting the delimiter to `"` only; regression test added, confirmed red-before-green.

## 2.0.0 — Ground-up rebuild (2026-10-08)

The entire extension was rebuilt from scratch at the user's request, due to accumulated tech debt in the v1.3 implementation. Nothing was deleted -- the previous implementation is preserved in full in `archive/legacy-v1.3/`. Feature parity was the explicit goal: same 4 platforms, same capture/filter/export features, architecturally clean instead of organically grown.

### What changed and why

**Architecture.** A 712-line `src/ui/controller.ts` doing manual `innerHTML` templating and imperative DOM patching is now a Preact component tree driven by a `@preact/signals` store -- no more special-cased re-render avoidance (the old code had a `refreshStatsLine()` function that existed purely to avoid stealing input focus on every tick). Four platform parsers that had each reimplemented their own version of "walk unknown JSON, extract queries, regex-fallback" (with real duplication, and in Gemini's case a heuristic function duplicated *within the same file*) now compose a shared toolkit (`src/core/extract/`).

**Two real correctness fixes, not just refactors:**
- Gemini's query-location matching used to build a formatted path string (e.g. `"[0][0][3][1][2]"`) and regex it -- fragile, since a literal object key like `"2"` could confuse it. It now compares real array-index sequences directly.
- Claude never extracted any sources in v1.3 (the field was always empty). It now does, defensively, covering every plausible web-search-result shape since claude.ai's internal API isn't externally documented.

**A real security fix:** CSV export didn't neutralize a leading `=`, `+`, `-`, or `@` in an exported cell -- a classic CSV/formula-injection vector if the file is later opened in Excel or Sheets. Fixed.

**A real test-coverage gap closed:** the old Gemini test suite explicitly only tested the regex fallback, with a comment admitting the real `batchexecute` path-indexed structure was "too complex to mock perfectly." The new suite constructs that real structure by hand and verifies the structural walk actually fires.

**CI was broken and nobody had noticed:** `.github/workflows/lint.yml` had a step literally labeled "Run ESLint" that actually just ran `tsc --noEmit` -- no real lint, no test step, no build step, ever, on any push or PR. Replaced with a workflow that runs typecheck, test, and build in sequence with a pinned Node version.

**Visual redesign:** the cyan/blue glassmorphic "AI HUD" look (read as generic/templated against a design audit, and its accent color nearly collided with Perplexity's own brand teal) is replaced with a neutral "analyst dashboard" direction -- solid surfaces, one desaturated accent, tighter radii, calmer motion.

**Accessibility fixes:** a permanent ARIA live region (the overlay was previously completely silent for screen readers on every dynamic update), `:focus-visible`-only focus rings, and `prefers-reduced-motion` handling for the live-dot pulse and expand/collapse transition.

**New, honestly-labeled states:** a composed empty state (replacing a bare text string), a loading skeleton gated behind a 400ms delay so the fast path never flashes it, and an error banner surfacing clipboard/download/storage failures that were previously silently swallowed.

**Dependency change:** `preact` and `@preact/signals` are the project's first-ever runtime dependencies (previously zero). Deliberately no `@preact/preset-vite` -- plain esbuild JSX transform keeps the content-script bundle lean.

**Dead code removed:** a separately Vite-built `content.css`, referenced in the manifest's isolated-world content script, which had nothing to style (the overlay's styling is 100% delivered via the Shadow-DOM-inlined stylesheet).

**Backfill redesign:** the old `conversation.ts` hand-duplicated a slimmed-down ChatGPT parser because MV3 content scripts can't safely share a module between two entries. The rebuild instead has `content.tsx` ask the already-loaded interceptor (which owns the real parser) to do the re-fetch-and-parse via a `postMessage` round-trip -- same real extractor, no duplicate.

### Migration notes

- Storage moved to a new, explicitly schema-versioned key (`csr:captures:v1`); the old flat key (`csr:capturesByConversation`) is read once for a one-time migration and never written to again.
- The data contract (`CapturedQuery`, `Source`) is unchanged -- nothing about what the extension captures or how it's shaped changed, only how it's produced and rendered.
