- [x] Fixed CI: it previously claimed to "Run ESLint" but only ran `tsc --noEmit`, with no test step, no build step, and no pinned Node version. Now runs typecheck + test + build on every push/PR, Node 22 pinned.

- [x] `@preact/signals` store replacing ~700 lines of manual `innerHTML`/DOM-patching, with an explicit `schemaVersion` and byte-budget guard replacing a silent `catch{}` on storage quota errors.

- [x] Removed dead weight: a separately-built `content.css` that had nothing to style (the overlay is 100% Shadow-DOM-inlined).
- [x] Full documentation pass: README, ARCHITECTURE, AGENTS, SKILLS, CHANGELOG, this roadmap, and regenerated store-readiness docs.

## Next

- [ ] **Perplexity capture is currently non-functional against the live product -- highest priority.** Found during the v2.0 live verification pass (2026-10-08): `PerplexityContext.shouldIntercept` looks for `/rest/sse/perplexity_ask` or `/rest/thread/...with_schematized_response=true`, inherited verbatim from v1.3. Live testing found **no matching request at all** for a real search on perplexity.ai -- no REST/SSE call, no GraphQL HTTP call, no XHR beyond an unrelated analytics beacon. The page ships chunks named `threadRelayEnvironment`, `threadLiveUpdates`, `client` (Relay, Facebook's GraphQL client), strongly suggesting Perplexity has since migrated its thread/query delivery to a Relay-based mechanism, most likely a WebSocket subscription given the complete absence of any matching HTTP traffic. This is **not a rebuild regression** -- the same endpoint assumptions were already stale in v1.3, just never caught before this live-testing pass. Properly fixing this requires actually capturing and inspecting the real wire traffic (e.g. a HAR capture or a WebSocket frame inspector) to learn the current protocol before writing new interception/extraction logic -- don't guess at it blind.
- [x] **Live verification pass (all 4 platforms).** Completed 2026-10-08 via browser automation with a real prompt ("I'm climbing Everest soon..."); found and fixed 5 real bugs along the way (see CHANGELOG.md's Unreleased section / git log): an AbortSignal DataCloneError and a Headers DataCloneError in the interceptor's worker-escape path, a relative-URL resolution failure in that same path (broke claude.ai entirely -- "Connection lost"), a `:root`-vs-`:host` CSS scoping bug that made the panel fully transparent, and an auto-expand behavior that let the opaque panel visually cover the host page's own Send button. All five are fixed, tested, and confirmed clean (zero console errors from our extension) on ChatGPT, Claude, and Gemini. Also surfaced the two coverage gaps below (Perplexity, Gemini extraction) -- real, pre-existing, not caused by the rebuild.
- [x] **Gemini extraction fixed -- the real cause wasn't schema drift.** Investigated 2026-10-08 after the live pass flagged it. The actual bug was architectural, in `interceptor.ts`, not Gemini-specific: the hook-cycle-escape branch (taken whenever another script on the page also wraps `window.fetch` -- gemini.google.com does this for essentially every request) returned the worker-forwarded fetch directly, completely skipping platform detection and `extract()`. Gemini's batchexecute calls never once reached the code path that would have processed them. Fixed by sharing one `attachExtraction` helper across both the direct and escape paths (see git log). Confirmed live afterward: a real query ("1 new query captured") showed up for the first time. That same test also caught a second, real bug: the generic `"text"` key in the fallback matcher (inherited from v1.3) was false-positiving on ordinary response prose (`{text: "I've been curious about..."}` from the assistant's own answer, captured as if it were a search query) -- removed, and a `webSearchQueries`-style array-of-strings shape was added based on Gemini's public grounding API, since the consumer product's internal schema plausibly mirrors it. Both fixes have regression tests. Still worth validating against more live queries to see what else turns up, but the platform is no longer silently non-functional.
- [ ] **Re-verify Claude's search capture now that the re-entrant extraction bug is fixed.** claude.ai also showed "fetch re-entry detected" during the live pass (Datadog wraps `fetch` there too) -- the same bug that silently blocked all Gemini extraction could plausibly have been blocking Claude's capture too, whenever a web_search response happened to arrive via the escape path. The live pass never got Claude to actually trigger a web_search tool call (it answered the Everest question from its own knowledge), so this was never confirmed either way. Needs a prompt that reliably triggers Claude's web search, tested post-fix.
- [ ] **Capture real vendor payloads as genuine golden fixtures** from the live-testing pass above, once Perplexity's and Gemini's current protocols are understood -- today's platform test fixtures are hand-built approximations, not captured traffic (see `src/platforms/*.test.ts`).
- [ ] **Validate Claude's source extraction against real traffic.** It's defensive/best-effort today (checks every plausible result-block shape) precisely because the real shape isn't documented; the live pass didn't trigger an actual web_search tool call from Claude to confirm this against -- needs a prompt that reliably triggers Claude's web search.
- [ ] **Real ESLint**, or an explicit decision not to bother. `npm run lint` is currently just an alias for `tsc --noEmit`; either wire up real linting or rename the script so it stops implying something that isn't there.

## Explicitly out of scope for v2.0

These came up during the rebuild's design discussion and were deliberately deferred, not forgotten:

- A persistent side panel instead of the floating overlay.
- Cross-conversation search history / search across all captured conversations.
- Side-by-side source comparison across platforms.

If any of these become a priority, they're new features on top of a now-clean architecture, not another rebuild.
